# IRAN 0.54.1 — یک نوبت پذیرش نهایی

بستهٔ Actions فقط پس از موفقیت Baseline، Core Quality روی Linux/Windows و Windows Jarvis روی **همان SHA** ساخته می‌شود. فایل RELEASE_MANIFEST.json داخل بسته commit دقیق، مسیر داده و dependencyها را ثبت می‌کند. بسته کد است؛ مدل‌های صدا و زبان و دادهٔ شخصی داخلش نیستند.

## نصب یا ارتقا روی Windows (Python 3.12)

برنامهٔ قبلی را عادی ببندید. هیچ process را اجباری نبندید. پوشهٔ قبلی را نگه دارید. از کل پوشهٔ قبلی به یک مسیر جدا نسخهٔ پشتیبان بگیرید؛ سپس بسته را در **پوشهٔ جدید** استخراج کنید.

برای ارتقا، در حالی که هر دو نسخه بسته‌اند، پوشهٔ data و فایل‌های محلی خودتان (reviewers.local.json و مدل‌های موجود) را از نسخهٔ قبلی به نسخهٔ جدید کپی کنید. اگر memory.db یا مسیرهای runtime را سفارشی کرده‌اید، همان مقدارهای مسیر را در config جدید نگه دارید؛ config قدیمی را کامل روی config جدید ننویسید. نسخهٔ قدیمی و پشتیبان را تا پایان آزمون نگه دارید. فایل خراب را حذف یا با دادهٔ خالی جایگزین نکنید.

در PowerShell داخل پوشهٔ جدید:
```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\launch_iran.ps1
```
اجرای CLI:
```powershell
.\.venv\Scripts\python.exe main.py
```
راه‌انداز ابتدا .venv سپس py -3.12 سپس python روی PATH را انتخاب می‌کند. قفل runtime اجازهٔ اجرای دو نسخه روی یک data را نمی‌دهد. خطای startup در gui_startup.log و کنسول قابل مشاهده است.

## آزمون واحد

1. خاطرهٔ قبلی واقعی را بپرسید؛ بعد نام و هدف دو پروژهٔ متفاوت را مرور کنید. فقط یکی را اصلاح کنید و هدف دیگری را دوباره بپرسید.
2. یک موضوع را توضیح بدهید، «ساده‌تر»، «مثال بزن»، «بیشتر توضیح بده» و تغییر موضوع/بازگشت را امتحان کنید. پاک‌کردن نمایش نباید حافظه را پاک کند.
3. برنامه را عادی ببندید و دوباره باز کنید؛ همان خاطره و اصلاح را بپرسید. «۲ + ۳» و سؤال زمان را بررسی کنید.
4. اطلاعات سیستم، باتری و screenshot موجود را با مجوزهای فعلی امتحان کنید. مجوز نوشتن یا کنترل ورودی به‌طور خودکار فعال نمی‌شود. عمل تأییدنشده نباید «انجام شد» بگوید.
5. برای صدا، GUI فعلی کنترل میکروفون متصل ندارد؛ adapterهای موجود را با دستور زیر یک بار روی دستگاه آزمایش کنید. کیفیت فارسی را خودتان با شنیدن ارزیابی کنید.
6. آنلاین فقط اگر OPENROUTER_API_KEY موجود و دسترسی واقعاً صفرهزینه مجاز است: اینترنت را در IRAN روشن کنید و وضعیت reviewer را ببینید. منبع → reviewer → تصمیم صریح شما → Gate باید حفظ شود. صرف کلید یا enabled بودن موفقیت اتصال نیست. OFF و restart را نیز بررسی کنید.

## آزمون صوتی دستگاه

dependencyهای اختیاری:
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-jarvis.txt
.\.venv\Scripts\python.exe evaluation/device_voice_acceptance.py --vosk-model "C:\path\to\existing-vosk-model" --piper-model "C:\path\to\existing-persian-model.onnx" --piper-executable "C:\path\to\piper.exe"
```
این مسیرها باید مدل‌های **واقعاً موجود** شما باشند؛ چیزی دانلود یا خریداری نمی‌شود. پنج ثانیه فارسی صحبت کنید؛ متن تشخیص را بخوانید و صدای خروجی را بشنوید. ساخت WAV جدا از پخش گزارش می‌شود. بازگشت تابع پخش اثبات شنیده‌شدن یا کیفیت فارسی نیست. Vosk بدون مدل/میکروفون در دسترس نیست؛ Piper به executable و مدل مناسب نیاز دارد.

## وضعیت موتور زبان و اتصال بیرونی

موتور local_http روی loopback موجود است و اکنون برای احوال‌پرسی محدود از مسیر IranRuntime.handle واقعاً فراخوانی می‌شود. پاسخ فقط از قالب‌های امن احوال‌پرسی پذیرفته می‌شود؛ پاسخ factual، حافظه، ابزار و یادگیری همچنان تصمیم CognitiveSystem هستند. این اتصال ادعای موتور زبانی عمومیِ پذیرفته‌شده نیست. نبود سرویس/timeout/خروجی نامعتبر fallback نمادین و رویداد local_language_fallback دارد. سرویس و وزن مدل موجود در بسته نیستند.

آزمون CI transport محلی واقعی از HTTP loopback استفاده می‌کند؛ مدل واقعی، میکروفون، speaker و اتصال provider بیرونی را تأیید نمی‌کند. reviewer کلیددار بدون OPENROUTER_API_KEY، quota و شبکهٔ قابل‌دسترسی BLOCKED_EXTERNAL است. endpoint پیش‌فرض زبان http://127.0.0.1:18080/v1/chat/completions است. free tier با بدون حساب بودن فرق دارد.

GitHub Actions تصمیم انسانی برای یادگیری نمی‌گیرد. probe زنده تنها transport و عدم اعمال خودکار را بررسی می‌کند؛ fixtureهای آزمون داخلی جای reviewer واقعی یا تصمیم شما نیستند.
